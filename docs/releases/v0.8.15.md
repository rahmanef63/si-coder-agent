# SI-Coder v0.8.15

SI-Coder v0.8.15 separates **connection source/backend** from **authentication method** so Composio, provider-native MCP, and SI-Coder direct credentials are no longer conflated.

## Connection model v2

The control-plane model is now:

```text
User → Provider → Connection → Source/backend → Auth → Scope
```

A connection's source is one of:

- `sc` — SI-Coder owns direct credential storage and injects the selected connection into child execution.
- `composio` — Composio owns the provider credential and SI-Coder keeps only safe connected-account routing/status metadata.
- `native-mcp` — the provider-owned MCP/OAuth flow owns authentication; SI-Coder keeps routing identity only.

The old metadata `source` provenance field is split: provenance such as `legacy-profile` is now `origin`, while `source` means credential/execution backend only.

## Composio Connected Account lifecycle

Composio is no longer exposed as a provider auth method such as `OAuth (Composio managed)`.

For `source=composio`, SI-Coder now supports the current Composio v3.1 Connect Link flow:

```text
resolve user-owned Composio project connection
→ resolve/pin Auth Config
→ create Connect Link
→ show transient redirect URL
→ persist safe connected-account IDs/status only
→ refresh status until ACTIVE
```

SI-Coder intentionally does **not** persist:

- OAuth access/refresh tokens,
- Connected Account credential `state`,
- Composio `link_token`,
- transient redirect URLs.

A Composio project API key remains a separate `Provider = composio` direct connection. This is the broker credential SI-Coder uses to call Composio's project-scoped Auth Config / Connected Account APIs.

## GitHub UX

GitHub direct authentication is now explicit:

- **Fine-grained PAT** — recommended when the needed repository/permission model supports the task.
- **Classic PAT** — compatibility / broad repository automation path.

Each path has its own official creation URL/navigation. Composio GitHub is instead:

```text
GitHub → Add connection → Composio → OAuth2
```

The Finder flow is source-first and the stable absolute cursor-addressed renderer introduced in v0.8.14 is unchanged.

## Metadata migration

Connection metadata is version 2. Existing v1 state is normalized read-only first. Explicit migration:

```bash
sc user connection-metadata-migrate --yes
```

creates a mode-`0600` v1 backup before persisting v2. Existing direct GitHub PATs are classified locally as fine-grained/classic without copying their secret value into metadata. Legacy external OAuth placeholders without a real Connected Account id become `needs-authorization`, never implicitly ACTIVE.

## Machine tools

The legacy machine-function surface remains **32 functions**. Connection tools now expose `source` independently from `authMethod`, and Composio-backed connections can be authorized/synced without accepting provider credentials in tool JSON.

SI-Coder remains the resolver/control plane: when `source=composio`, agents should use the resolved toolkit + connected-account id/alias directly for provider execution rather than adding an unnecessary SI-Coder wrapper around every Composio tool call.

## Additional fixes

- External metadata-only connections no longer create empty local credential `.env` files.
- Fixed exact named-connection credential deletion so a removed field cannot be reintroduced by merge-write behavior.
- Added sandbox migration coverage and mocked Composio lifecycle tests that assert provider credential state never reaches SI-Coder metadata/output.
