# SI-Coder v0.9.1

> **Historical release record.** This file preserves what v0.9.1 shipped. For current behavior and install guidance, use the repository README and current install docs.

SI-Coder v0.9.1 closes the post-v0.9.0 usability and documentation gap without rewriting the v0.9.0 release history. The user-facing model stays simple—**SC is one coding/publishing tool**—while provider auth, terminal navigation, docs, and release metadata are aligned behind that surface.

## What changed

### Simpler product/documentation surface

- README keeps the one-tool mental model first and moves engineering internals behind progressive disclosure.
- Current installation docs are separated from historical release notes; every older release note is explicitly labeled historical instead of having its old wording silently rewritten.
- Current version metadata is aligned across `package.json`, Claude plugin metadata, OpenAI/Codex plugin metadata, install links, and this release note.

### GitHub direct auth is PAT classic only

For `github` with `source=sc`, SI-Coder exposes exactly one direct auth method:

```text
classic-pat → GITHUB_TOKEN (ghp_…)
```

Create it at `https://github.com/settings/tokens/new`. The UI/tool handoff explains **Settings → Developer settings → Personal access tokens → Tokens (classic)** and recommends a limited expiration plus only the scopes the task needs (`repo` when private-repository automation is required).

Existing direct metadata that used the previous `personal-access-token` or `fine-grained-pat` label normalizes to `classic-pat`. A stored `github_pat_…` value is not silently accepted; direct validation fails and SC guides the user to rotate it. GitHub via `source=composio` remains a separate OAuth-backed connection path.

### Clearer Finder TUI navigation

- `Esc`/`←` goes back one layer.
- `Esc` at Home does not quit; Quit/Ctrl-D remains explicit.
- During hidden or visible credential/metadata input, `Esc` cancels only that input, writes nothing, and returns immediately to the previous SC screen.
- The lower `INFO` + `PREVIEW`/`RESULT` panel now uses more vertical space: 8 detail rows on a normal 28-row terminal, 6 on medium, 4 on compact terminals.

### Tool-calling stays secret-safe

No secret-bearing machine schema was added. `sc.user.connection.request` derives GitHub's current direct auth choices and setup URL from the provider SSOT, so MCP/machine clients now receive `classic-pat` + the classic-token URL without ever accepting the token value in JSON.

### Current ChatGPT distribution wording

OpenAI's current Help Center documents uploaded Skills for eligible ChatGPT **Business, Enterprise, Healthcare, and Edu** workspaces, subject to workspace settings/product availability. Current SI-Coder docs therefore distinguish:

- uploaded Skill package (`sc.zip`) for eligible workspaces that expose Skill upload; and
- GitHub plugin marketplace import for managed workspaces.

Historical release notes keep their original terminology but are marked historical.

### Cleanup

- Removed an unused credential-read local and an unused prompt option from the TUI credential path.
- Renamed the current ChatGPT install guide from `chatgpt-personal-skills.md` to `chatgpt-skills.md` so the filename no longer implies universal personal-plan availability.
- Kept canonical/generated boundaries intact: `skills/*` remain source, `plugins/si-coder/skills/*` remain generated copies, and `machine/functions.json` remains the standalone machine SSOT.

## Verification

Release verification covers current Markdown/link consistency, provider/auth tests, Finder/TUI regression, machine/MCP secret-safety, deterministic distribution artifacts, strict skill validation, secret scan, and the full repository test suite.
