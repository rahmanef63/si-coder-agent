# SI-Coder v0.9.0

SI-Coder v0.9.0 makes the agent engineering loop fully standalone and repo-local: risk classification, task preparation, memory, evidence, repeated-work recipes, strict skill validation, and verification now live inside SI-Coder without requiring a sibling project or external orchestrator.

## Standalone machine contract

The machine-function SSOT moved from a host-specific namespace to:

```text
machine/functions.json
```

`scripts/sc-mcp.js` reads this manifest directly and exposes it over standard MCP stdio. External runtimes are optional consumers; SI-Coder does not require them to install, configure, run, or verify its core workflow.

The machine surface now contains 43 bounded functions. New agent workflow functions are:

```text
sc.task.risk
sc.task.prepare
sc.memory.query
sc.memory.record
sc.memory.status
sc.evidence.record
sc.recipe.list
sc.recipe.observe
sc.recipe.verify
sc.recipe.promote
sc.skill.verify
sc.verify
```

## Risk-based isolation and context preparation

`sc risk` classifies LOW / MEDIUM / HIGH work. HIGH-risk changes such as credentials, auth, migrations, provider abstractions, machine/MCP schemas, distribution, and security-sensitive changes require isolation.

`sc task prepare` keeps context small:

- LOW risk: do not load repository memory;
- MEDIUM/HIGH risk: rank and inject only relevant memory plus applicable recipes.

## Repo-local memory

Canonical memory is portable Markdown + frontmatter under `.agent/`:

```text
.agent/
├── memory/
│   ├── tasks/
│   ├── debug/
│   ├── tests/
│   ├── decisions/
│   └── failures/
├── recipes/
├── scripts/
└── evidence/
```

Memory supports lifecycle state, confidence, scope, tags, commit, `last_verified`, and supersession. Retrieval marks old records stale and can require fresh-only results instead of silently treating old provider behavior as current fact.

## Evidence and Test Memory

`sc verify` records a compact Evidence Receipt and Test Memory by default. Evidence stores structured assertions and quality-gate results instead of raw test logs.

Memory/evidence/recipe writes reject secret-shaped content before persistence, and the existing recursive machine-input guard remains in place.

## Recipe → executable script

Repeated workflows progress:

```text
observed → repeated → candidate → verified → executable
```

Successful recorded repository verification observes the release-candidate sequence. Read-only release checks never mutate recipe state. A verified recipe can be bound only to an existing repository-local deterministic script; escaping paths/symlinks are refused.

`npm run verify:release` is the deterministic release-candidate script and emits structured syntax/tests/docs/distribution/skills/secret-scan status.

## Skill quality

All canonical SI-Coder skills now extend the existing frontmatter schema with explicit:

- `use_when`;
- `do_not_use_when`;
- `required_tools`;
- `security_constraints`;
- `references`;
- `compatibility`.

`sc skill verify --strict` validates metadata, trigger clarity, references, declared tools, secret-shaped content, duplicate prose, and compatibility. Fenced code examples are excluded from duplicate-prose detection.

## Standalone cleanup

User-facing documentation no longer assumes another internal project. Provider examples were generalized where repository-local documentation had accidentally embedded environment-specific domains, projects, workflow names, backup paths, or sender identities.

The n8n and Resend skills now require explicit user/project configuration instead of carrying one deployment's infrastructure as a default.

## Verification

The release is gated by targeted agent-workflow tests, full repository regression, strict skill validation, documentation synchronization, deterministic package regeneration, secret scanning, machine/MCP schema checks, and git diff review.
