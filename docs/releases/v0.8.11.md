# SI-Coder v0.8.11

> **Historical release record:** behavior, installation labels, and provider recommendations below reflect this release at the time it shipped. For current guidance, use [`../install/README.md`](../install/README.md).


SI-Coder v0.8.11 replaces the single-provider-credential mental model with labeled, scoped provider connections inspired by Composio's multi-connected-account model.

## Highlights

- New hierarchy: `User → Provider → Connection(alias) → Credential fields`.
- One user can own multiple independent connections for the same provider, each with a unique label, auth method, scope, default flag, and private `0600` secret file.
- Finder now adds a `Connections` layer while preserving the existing four-column sliding layout.
- Added connection CRUD, legacy migration, and one-shot execution overrides with `sc run --connection provider=alias -- ...`.
- Existing legacy profile credentials can be migrated locally into named connections without printing values.
- Convex self-hosted and Convex Cloud are explicitly separated.
- Convex Cloud supports:
  - account/admin Personal Access Token (`BEARER_TOKEN`, account scope), and
  - Deployment Name + Deploy Key (`API_KEY`, deployment scope).
- Added Convex Personal Access Token endpoint: `https://dashboard.convex.dev/profile#personal-access-tokens`.
- Composio project API keys and organization API tokens are separate connection types.
- Provider auth metadata now records OAuth/API key/Bearer/DCR OAuth/local methods and scope where relevant.
- Added current Composio/provider auth research under `docs/research/composio-auth-matrix.md`.
- machine/MCP remains secret-safe with exactly 32 functions. New tools manage/list/request named connections; credential tools accept an optional connection alias.
- OAuth/external auth handoffs return alias/toolkit metadata instead of asking for OAuth/access tokens in JSON.
- Custom providers can define click navigation with `--navigation "Settings > API Keys > Create"`.

## Live migration contract

Migration copies each provider's values into a private named connection first and removes the migrated legacy fields only after the new connection files exist. Values are never printed. The total number of stored credential fields should remain unchanged.
